# Pebrel 基础体验重整

用户已认可原型方向，随后明确暂停继续制作原型，直接开发原生界面。
保留原项目的完整设置、文件树、文件预览/编辑、SSH、手机连接与备份等能力，
在现有 Rust/GPUI 主体中分批整理导航、Git 审阅和额度详情。

原型：[打开 index.html](prototypes/2026-10-26-workbench/index.html)。
直接在本机浏览器打开即可，引用仓库已有图标，无需安装依赖。
全部数据保存在页面内存，刷新恢复初始状态；不读取会话、认证或 Git，不执行命令。

## 一套操作路径

1. 在项目选择器确定项目，从会话列表直接进入任务。
2. 从会话的「查看改动」进入仓库审阅，默认左右对照。
3. 点击行只选择，不跳转输入框；明确点击「添加意见」后开始写。
4. 跨文件累计意见，审阅完打开「待反馈」，核对文件数、意见数和目标 Agent。
5. 左下角只看官方额度百分比；摘要进入设置中的用量详情，返回时保留工作区。

## 删除、合并、保留

| 位置 | 改造前的问题或风险 | 处理方向 |
| --- | --- | --- |
| 项目导航 | 选择器和树根重复当前项目 | 单项目时只保留选择器；全部项目视图仍可按项目分组 |
| 会话树 | 单终端又出现同名子节点 | 单终端一行直达；有多个分屏才显示展开入口，按原生 ID 定位 |
| 会话树 | 展开、切换、选中混在一起 | 展开按钮只控制展开；名称定位当前分屏；不因收起改变当前终端 |
| 文件与差异 | 文件标签挤入会话层级 | 单独归类；保留原文件抽屉，审阅使用自己的文件列表 |
| Git | 选中差异就打开并聚焦批注 | 选择和评论分开；保留复制、连续阅读和左右同步滚动 |
| Git | 单文件按钮实际发送整个仓库意见 | 显示待反馈队列，明确全部文件/意见与目标 Agent，再预览发送 |
| Git | 换文件可能丢失尚未加入队列的文字 | 草稿按仓库与文件保存；隐藏输入框或切换文件不丢失 |
| Codex | 容量、采样诊断、账号和重置卡顺序分散 | 账号 → 官方窗口 → 容量摘要 → 重置卡；诊断与本机记录折叠 |
| Codex | 摘要和详情缺少连续入口 | 百分比摘要进入同一账号的设置详情；读取失败显示旧数据标记 |
| 配置 | 容易继续增加另一套管理界面 | 供应商、路由、MCP、Skills 仍由 CC Switch 负责 |

保留既有主题与组件、终端交互、原生会话身份、历史入口、Git 执行队列、
原始 patch、快照校验、额度来源和本机用量的不完整标记。

## 原型可体验内容

- 页顶切换三页；原型控制条不属于未来的原生产品界面。
- 单终端会话直接切换；多分屏用独立展开按钮展开，名称进入原有分屏。
- Git 切换文件、左右/原始视图、单行/Shift 连选、明确添加意见。
- 未提交文字按文件保留；加入队列的意见可跨文件查看、移除、定位和预览。
- 队列明确整批发送范围并可选择 Codex/Claude；演示发送保留意见，不实际投递。
- 「演示状态」可切换意见失效，显示阻断原因并禁止整批发送。
- 暂存状态仅在原型中切换；每个示例文件用一个更改块演示。
- 额度摘要进入设置；展示正常、加载、读取失败、已有容量参考四种状态。
- 估算依据、重置卡列表、本机记录按需展开；本机今日/本月分别展示。
- 历史、新建、分支、文件入口只示意位置与范围，不复刻完整现有功能。

## 原生改造顺序

### 第一批：会话导航

主要入口：gpui_shell/workspace/projects.rs、project_tree.rs、
project_tree/sessions.rs、sidebar.rs、tab_presentation.rs。

- 单项目视图取消重复项目根；全项目视图保留项目层级。
- 分屏数为 1 时不渲染展开按钮和子节点；多分屏仍使用原生 TabId/pane ID。
- 在共同父级统一图标、名称、工具和状态列；每级缩进 16 逻辑像素。
- 展开状态与聚焦状态分离，保留已有重命名、关闭、拖放及恢复能力。

验收时看：同一个项目名不再连续重复；单终端只一行；展开与收起不切换任务；
多分屏定位正确，选中背景不会在父子两层重复。

### 第二批：Git 审阅

主要入口：gpui_shell/code_tab/diff/comparison.rs、code_tab/review.rs、
workspace/review.rs、workspace/vcs_panel/。

- 先移除行选择时自动打开输入并抢焦点的行为。
- 再统一反馈队列范围、目标选择、失效提示与预览；明确同仓库全部意见。
- 将预览与草稿生命周期理顺后，才复用单个文件预览位。可编辑草稿应有同仓库、
  同文件的唯一归属，不从多个标签另算一套数量；切换、关闭预览不默默丢弃文字。
- 保留现有 patch 字节选区、快照验证和写入队列；新增对照视图的行号不替代 patch 身份。
- 保留分支、新建分支、全部取消暂存、stash/Worktree 现有能力，收敛到更改区入口。

验收时看：浏览不弹输入；跨文件意见不丢；发送前能看清文件数和意见数；
其他文件意见失效也有明确位置；写入前仍检查当前仓库和所见快照。

### 第三批：Codex 信息归位

主要入口：gpui_shell/workspace/usage.rs、settings_pane/codex_usage.rs、
codex_usage/capacity.rs、codex_usage/entitlements.rs；只在必要时调整 ai_usage 的展示模型。

- 摘要和详情使用同一账号、套餐及官方窗口状态；保持数据来源与各自更新时间。
- 设置页先显示账号和官方额度；容量只给区间或简短不可用原因，详情折叠。
- 重置卡数量先可见，卡片详情及确认按需打开；实际兑换仍手动确认。
- 未读到额度显示未知，刷新失败保留旧数据并标记；不能当作 0% 或新鲜结果。
- 本机 tokens 单独展示，不换算为官方已用百分比；partial 仍是已确认下限。
- 换账号、窗口、模型、推理强度或速度档时，沿用既有采样隔离与失效规则。

验收时看：底部、摘要、设置显示的账号和窗口一致；找不到容量时能看懂原因；
加载/失败不出现假零值；本机记录与官方窗口不会混在一条进度中。
