# 项目归属与会话筛选

## Status

Implemented in the Pebrel Lele fork.

## Context

工作区原先只有一份平铺的标签列表。多个目录并行运行 Agent 时，需要按项目
选择会话，同时保留现有 PTY、分屏、Runtime API 和手机连接的生命周期。

终端的 cwd 会随 `cd`、WSL 或 SSH 改变，不能把实时 cwd 当作项目归属。

## Evidence

- [`TabMeta`](../../../../../../nebula_app/src/gpui_shell/workspace/tab_presentation.rs)
  与标签同下标移动，并通过唯一插入、移除和排序入口维护。
- [`session.rs`](../../../../../../nebula_app/src/session.rs) 的 v4 快照已经保存
  标签、分屏、启动身份与窗口布局；保存和导出使用同一格式。
- [`tab_scroll.rs`](../../../../../../nebula_app/src/gpui_shell/workspace/tab_scroll.rs)
  原先将存储下标直接作为侧栏的可见行下标。

## Decision

每个标签的 `project_root` 是显式项目归属；新建项目选择一个本地目录并创建首个
终端。已有标签可以通过右键菜单移动到一个项目，或移回未分组。

`TabMeta` 拥有运行时归属；终端快照的可选同名字段负责保存、恢复、复制和导出。
字段使用 serde 默认值，保持 v4 的旧快照可读取；旧会话不会按 cwd 被自动迁移。
文档标签只在本次窗口内跟随所属项目，不改变原有“只保存终端”的合同。

项目列表由标签归属派生，不维护第二份项目注册表。关闭或移走最后一个属于该
项目的标签后，项目从此窗口的选择器消失。当前项目筛选是窗口级临时呈现状态，
重启默认显示全部项目。

筛选只产生“可见行位置 → 存储下标”的映射，不重建、暂停或关闭任何终端。
侧栏滚动、拖拽排序、数字快捷键和相邻切换共用这个映射；Runtime API、Quick Jump
与跨窗口传输继续使用原有标签和 pane 身份。全局入口激活其他项目的标签时，
侧栏跟随真实活动标签切换项目。顶部标签模式继续展示全体标签。

在明确选中的项目内，默认新建终端从项目目录启动；其他启动方式保留其原有
shell、SSH 和 WSL 参数。复制标签、AI 分叉和拆出 pane 继承来源项目；合并标签
时，pane 随目标标签的项目归属。

原生目录选择任务由工作区持有，禁止重复打开；窗口实体销毁后不能回写结果。
异步移动以现有 `TabId` 寻址，目标关闭时报告失败，不按旧下标误改其他会话。

## Rejected alternatives

- 根据每次 cwd 上报重新分组：进入子目录或远端目录会让会话自动换组。
- 另建项目数据库或每个项目新建进程：引入第二份会话权威及额外生命周期。
- 对过滤后的列表继续使用全局行号：滚动、拖拽和快捷键会命中错误位置。

## Consequences

项目目录作为普通路径写入会话文件，不包含新的凭据或网络请求。
手机端与 Runtime API 的会话控制协议保持原有身份合同，不新增项目协议。
项目选择器属于 GPUI 壳；旧壳和旧版本不保留其不认识的可选项目字段。

## Validation

Windows debug 产品构建通过。相关自动测试共 275 项通过，其中 231 项工作区测试
覆盖筛选后的标签身份、排序、复制、全局激活，以及用量浮层的布局和输入事件；
40 项会话相关测试覆盖旧快照兼容与项目字段保存恢复。

隔离配置下启动原生程序，通过 Runtime API 在两个项目的终端执行命令并核对 cwd；
重启后两个已保存会话的项目归属与 cwd 一致。QA-A 的关闭经用户确认是手动操作。
原生目录选择器、鼠标交互、跨窗口及手机实机仍需人工验收；本机窗口自动化管道
不可用，GPUI 测试不等同于原生视觉验收。

## Supersedes

None.

## Revisit when

需要保留没有打开会话的项目、给手机端提供项目筛选，或让旧壳编辑项目归属时。
