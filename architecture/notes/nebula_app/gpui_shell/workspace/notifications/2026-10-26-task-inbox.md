# 任务通知中心投影现有会话事实

## Status

Implemented in source; 尚未构建及原生交互验收。

## Context

短暂 toast 和侧栏徽章不方便回看多个项目的待确认/失败/完成事项。现有通知管道和
pane 生命周期已经决定事件及运行状态，新面板只需要汇总和定位。

## Evidence

- `workspace/notifications.rs` 在既有通知交付前记录事件，不改变声音或系统通知策略。
- `workspace/task_inbox.rs` 持有面板、筛选和最多 256 条内存记录。
- `terminal/view/runtime.rs::sidebar_activity` 继续提供当前运行/等待/失败事实。

## Decision

通知中心按本窗口和 pane ID 定位，不创造第二套 Agent 状态机。运行中、待输入与
当前故障来自现有生命周期；历史事件只负责未读、错误回看和原始来源。项目范围
默认跟随筛选，可显式包含全部项目。事件记住发生时的项目，运行态使用当前项目。

列表不写磁盘，不复制完整回答；标题/正文和条数有界，相同失败重试合并显示。
已读仅表示看过，不代表批准或解决故障。关闭来源会话后保留历史卡片并禁用定位，
不把标题匹配的其他会话当作原会话。激活来源 pane 或显式操作可标记已读。

焦点、Escape、外部点击和工作区销毁沿用现有原生浮层生命周期。跨窗口移动后的
来源跳转不在这一版中猜测处理，面板明确标为本窗口。

## Rejected alternatives

- 从静默时间或屏幕关键字再判一次完成：会覆盖现有 hook/协议事实。
- 新增云通知/远程连接服务：现有手机控制与桌面通知已有独立职责。
- 已读直接批准、已关闭时按标题恢复：缺少操作授权及稳定身份。

## Consequences

重启后通知列表清空；原生会话历史是另一项持久功能。手机任务列表后续应复用同一
身份和生命周期事实，不能把桌面临时通知表当作新的权威状态。

## Validation

源码核对；未运行构建、测试或真实通知/手机验收。

## Supersedes

None.

## Revisit when

需要跨窗口通知归属迁移或用户明确要求持久化通知历史时。
