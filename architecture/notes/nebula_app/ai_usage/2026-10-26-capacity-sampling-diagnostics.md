# 容量采样诊断与原生权益核对

## Status

Windows GPUI debug 产品构建通过（123503）。 Reset redemption remains untested.

## Context

单一“待采样”无法解释容量估算为什么不可用；不能通过放宽来源或补造缺失的
模型/速度档位来生成数值。

## Evidence

- 只读官方接口与本机原生 Codex App Server 均返回 2 张可用重置卡，未兑换。
- 抽样日志的 provider 为 OpenAI 别名；存在混合模型及缺失速度档位。
- 抽样 8 个档案存在 13 条 TTFT 字段记录，原生解析器已读取对应字段；
  tok/s 保持完整回合均速约算口径。

## Decision

保留严格来源归因、连续区间、账号/套餐/窗口一致性及模型/effort/tier 分组要求。
设置页显示来源不明、信息缺失、混合模型、中断等具体原因，以及模型配置、窗口、
记录数和已观测百分点。缺少有效样本时不显示官方 token 余额或推算假数值。

采样原因作为 Observation 中可选嵌套字段存储；旧文件缺失字段可读，旧版本
可忽略新嵌套字段。不会向 deny_unknown_fields 的顶层 Store 增加必需字段。
短间隔观测仅在相同账号修订和窗口下沿用原因。

## Rejected alternatives

- 仅按供应商别名大小写认定历史请求的官方来源：同名配置可能曾路由到不同服务。
- 从当前配置填补历史请求的速度档位：CLI 覆盖与中途配置变更会使估算失真。

## Consequences

当前日志仍可能无法产出容量估算，但原因可见。查询成功不代表重置卡兑换或
设置面板的原生交互已经验收；不自动兑换或变更 CC Switch 配置。

## Validation

完成只读权益对照及匿名字段/数量核对；完整产品构建结果见清单。未打印凭据、
原始 ID 或对话，不增加采集进程。

## Supersedes

扩展原有权益与校准规则的诊断，不改变计量与兑换边界。

## Revisit when

原生来源可证明官方别名映射、缺失档位字段有可靠契约或官方提供直接容量时。
