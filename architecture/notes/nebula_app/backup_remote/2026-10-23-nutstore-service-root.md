# 坚果云服务根地址与归档目录

## Status

Implemented in the Pebrel Lele fork.

## Context

用户使用官方 WebDAV 服务地址 `/dav/`，目录读取成功，但执行备份时报创建目录
HTTP 403。把服务根地址直接作为归档目录，不能仅凭读取成功认定上传路径可用。

## Evidence

- [`backup_remote.rs`](../../../../nebula_app/src/backup_remote.rs) 原流程在 PUT
  返回 404/409 后对同一目标目录执行 MKCOL，失败时覆盖原 PUT 状态。
- 本次现场配置的路径为 `/dav/`，用户报告该回退创建目录返回 403。
- 实际专用目录验证：MKCOL 201、PUT 201、GET 200 且内容一致、DELETE 204。
  使用应用所依赖的 ureq 3.3.0 再次完成 PUT/GET/DELETE；临时文件只含随机测试
  内容，均已移除，没有执行旧归档清理。

## Decision

WebDAV 后端区分配置中的服务地址与实际归档目录。仅对 HTTPS、默认端口或显式
443、精确主机 `dav.jianguoyun.com`、无查询参数的 `/dav` 服务根地址，使用
`pebrel_backup` 子目录存放归档。已有自定义子目录及其他服务商保持原路径。
所有上传、下载、列表和保留规则共用后端的实际归档目录，不在 UI 复制此规则。

首次连接若专用目录不存在，只对服务根地址执行 Depth 0 的只读 PROPFIND；
服务端明确返回成功才作为空列表处理，认证、权限和其他失败继续上报。
MKCOL 仍只发生在用户执行备份时，并使用带尾部斜杠的集合 URL。创建失败时
同时保留初始 PUT 状态，不能让回退错误掩盖最初失败。

## Rejected alternatives

- 对服务根目录反复 MKCOL：无法修正归档位置，还会掩盖上传错误。
- 在连接检查中上传文件或创建目录：改变已有只读连接检查合同。
- 所有 WebDAV 地址都追加应用目录：破坏用户指定的自定义目录和其他服务商语义。
- 目录 404 一律视为可用：没有验证真实服务端及认证状态，会产生假成功。

## Consequences

配置仍保存用户输入的服务地址，不迁移配置格式或凭据。归档命名及保留边界
不变，只在实际应用目录内生效。连接检查验证读取连通性，写入是否成功仍以
真实备份操作结果为准。

## Validation

24 项后端测试和 7 项备份设置 GPUI 测试通过。扩展现有 HTTP 回环测试，覆盖
服务根地址映射、自定义地址不变、目录缺失时的只读回退、认证失败、首次上传
建目录后重试，以及保留 PUT 与 MKCOL 两阶段错误。
实际专用目录的测试文件上传、读回校验及删除通过；未代替用户生成完整配置备份。
Windows debug 产品构建通过；新版使用原测试配置启动，4 个已保存会话恢复成功。

## Supersedes

None.

## Revisit when

坚果云改变服务根目录语义、应用目录约定，或需要迁移其他已存在的归档位置时。
