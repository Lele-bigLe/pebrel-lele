# 原生历史正文预览与用户批注

## Status

Windows GPUI debug 产品构建通过（123503）。 Native interaction acceptance pending.

## Context

用户要求在已有项目/工具筛选、搜索和继续会话之外，增加正文预览、收藏和备注。
正文继续由各 CLI 管理，不能因浏览历史建立另一份会话库。

## Evidence

- `ai_sessions/transcript.rs` 读取原生 JSONL、Gemini JSON 或只读 OpenCode SQLite。
- 本机 OpenCode `message`/`part` 表已只读核对主键、会话关联、时间及 data 字段。
- `workspace/history/details.rs` 拥有加载、编辑和保存任务，关闭弹窗不影响原生档案。

## Decision

最近 500 个原生会话与已保存收藏/备注的定位提示合并，仍按工具和原生 ID 去重。
缓存定位提示不作为新的正文来源；缺失原生文件时明确报不可预览，继续会话仍走
原来的原生身份、重复实例检查和项目恢复链。行内预览按钮与原有点击/Enter 继续分开。

Codex/Claude 正文只读最近 2 MiB JSONL，Gemini 沿用 8 MiB 单 JSON 上限；
预览最多保留 80 条、合计 128 KiB 文本，单条最多 32000 字符。截断、未读完或
解析跳过均标记部分预览。排除系统注入、工具载荷与推理字段，只展示可读消息。

`ai_session_annotations.json` 仅保存收藏、最多 1000 字符备注及原生定位/标题提示，
位于权威应用数据目录；不复制正文。总量最多 2 MiB、4096 条。保存先取得既有
文件锁，重读并比较该条原值，再私有原子替换；跨窗口冲突要求重新打开，保留输入。
未知字段、无效 JSON 或超限不会回退空数据后覆盖。读取/写入均在后台任务执行。
读取与写入共用字段校验，防止超长定位信息写入后无法重读；每次保存尝试先清除
旧成功提示，失败时不沿用“已保存”。

## Rejected alternatives

- 将正文复制到 Pebrel 数据库：重复原生存储并扩大隐私、备份和同步边界。
- 直接修改 CLI 历史或复用有淘汰规则的 Hook 索引存备注：破坏原生身份与索引职责。
- 关闭弹窗自动保存或覆盖另一窗口的新值：造成无意写入或丢失备注。

## Consequences

不支持或缺失的原生格式仍可通过原 CLI 继续。旧定位提示可能过期，明确显示
“已保存的会话”，不伪造更新时间。新增元数据的备份衔接仍需单独核对。

## Validation

历史功能阶段产品构建通过；完整合并构建结果见产品清单。未输出原始会话正文，
未执行真实继续会话或写入用户收藏/备注。

## Supersedes

扩展 `2026-10-23-project-history-picker.md` 的最近 500 条范围与无收藏/备注限制。

## Revisit when

需要全量分页、其他原生格式或跨设备元数据时。
